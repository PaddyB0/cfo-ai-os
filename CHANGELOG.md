# Changelog

All notable changes to this project are recorded here, newest first. The format follows Keep a Changelog, and versions follow Semantic Versioning. Each entry says which template regions changed, so a deployer knows what an upgrade will touch.

## 0.3.0 - 2026-11-13

Breaking layout change. A 0.2 folder cannot be upgraded in place: `upgrade` and `check` refuse it. Deploy a new folder and move your files across by the table in `docs/upgrade.md`, section "Moving from 0.2".

### Added

- Tier folders `CFO/`, `VP/` and `Team/`, each with `Role.md`, `Memory/Now.md`, `Memory/Log.md`, `Periods/` and `Projects/`. `deploy --tiers` chooses which are written; `CFO` is always one. `upgrade --tiers` can add a tier and never removes one.
- `SETUP.md`, a setup prompt a person pastes into Claude to build the folder with no install, generated by `cfo-os prompt --out SETUP.md` from `src/cfo_os/setup_prompt.md`. `prompt --check` fails when it is stale; CI runs it.
- Hand-deployed folders: `check` and `upgrade` accept the manifest the setup prompt writes (`deployed_by_hand`). `upgrade --take-template` replaces every region that differs from the template, on any folder.
- `tier` on each row of the `people` answer. Deploy refuses a tier that is not `CFO`, `VP`, `Team` or `none`.
- `deploy --catalogue-exclude` and `catalogue --exclude` leave metrics out of the shared metric catalogue, which every tier can read. The manifest keeps the ids as `catalogue_exclude`, `upgrade --catalogue` applies them, and the setup prompt asks which metrics to leave out.
- The template ships inside the installed package, so `cfo-os deploy` works after `pip install` with no clone on disk.
- `docs/roles.md`: the tiers, the folder access to set, and what that access does and does not enforce.
- Tests for tiers, the setup prompt, hand-deployed upgrades and the new check rules.

### Changed

- The layout. Everything shared lives in `Shared/`: `Shared/Workflows/` (one file per job, flat, with `Templates/`), `Shared/Claude/` (instructions, context, rules, changelog, manifest, tests) and `Shared/Library/`. `START HERE.md` is `Read me first.md`.
- The Claude Project needs one line from `Read me first.md` in its instructions instead of the pasted `Instructions.md`, so it never needs pasting again.
- Memory is per tier: `Now.md` holds the current position and open questions and is rewritten; `Log.md` holds dated lines tagged Decision, Lesson, Question or Answer.
- `Company.md` now holds people and glossary.
- Each workflow's Trigger starts with its cadence: Monthly, Quarterly, Annual or On request.
- `check` enforces the new filing rules, accepts `Log <first name>.md`, notes tier folders it cannot see instead of reporting them, and reports a tier folder the manifest's tiers do not list.
- The plugin skills point to the new paths. The plugin's version in the marketplace entry is the package version.

### Removed

- `cfo-os pasted` and the manifest's record of the pasted instructions.
- `00 System/Folder map.md`; the rules are in the Instructions `filing-rules` region.
- `Start session.md` and `Close session.md`; folded into the Instructions `start` and `finish` regions.
- `People.md`, `Glossary.md`, `Key findings.md`, `Open questions.md`, `Decisions.md` and `Lessons.md`, folded into the files above.
- The numbered top-level folders and the placeholder README files in empty folders. `Shared/Library/`, `<tier>/Archive/` and `Shared/Workflows/Templates/Examples/` are created when first needed.

### Template regions

Every system file has a new path, so on a fresh 0.3 deploy every region below is new.

- `Shared/Claude/Instructions.md`: `start`, `roles`, `filing-rules`, `connector-rules`, `every-figure`, `output-rules`, `finish`. `roles` and `finish` are new; the others are rewritten.
- `CFO/Role.md`, `VP/Role.md`, `Team/Role.md`: `body` (new files).
- `Read me first.md`: `body` (was `START HERE.md`).
- `CLAUDE.md`: `body`.
- `Shared/Claude/Tests/Test questions.md`: `runs` (new), `questions`, `pass-rule`.
- `Shared/Workflows/`: `body` in every workflow: `Board or investor question.md`, `Board pack.md`, `Budget.md`, `Cash runway.md`, `Forecast critique.md`, `Investor reporting.md`, `Management accounts.md`, `Month-end close.md`, `Quarterly accounts.md`, `Year-end and audit.md`.
- `Shared/Workflows/Templates/`: `body` in `Board pack.md`, `Investor update.md`, `Management accounts.md`, `Management memo.md`, `Variance table.md`, and `Project brief.md` (new).
- `Shared/Workflows/Workflow template.md`: `body`.

## 0.2.0 - 2026-11-03

### Added

- A Claude plugin, `cfo-os`, in `plugin/`, with this repository as its marketplace. Three skills, each doing its arithmetic in a bundled standard-library script:
  - `cash-runway`: closing cash projected from an actual opening balance and one forecast cycle, the month cash falls below a floor, a tie to the forecast's own closing cash, a trailing-burn check and sensitivities.
  - `variance-analysis`: a variance table with favourable or adverse decided from line type and sign convention, materiality, totals tied to their lines, and a price, volume and mix bridge that adds up exactly.
  - `forecast-accuracy`: net error, WAPE and bias of the previous cycle on closed months, steps from run rate in the new cycle, and the full year spliced at the reference month.
- `cfo-os skills --out <folder>`: packages each skill as a reproducible zip for upload in the Claude apps.
- An eval suite in `plugin/evals/` and `docs/skills.md`: what ships, how to install it, and when a workflow becomes a skill.

### Template regions

- `04 Workflows/Monthly/Cash runway.md`, `04 Workflows/Monthly/Forecast critique.md` and `02 Rules and style/Templates/Variance table.md`: `body`. Each gains one line pointing to the matching skill when it is installed. The steps are unchanged.

## 0.1.1 - 2026-11-02

### Added

- `CLAUDE.md` in the `CFO OS` folder (template region `body`), read by Claude when the folder is opened. It points to `START HERE.md` and `00 System/Instructions.md`.
- `AGENTS.md` and `CLAUDE.md` at the repository root, for coding agents working on the template.

### Fixed

- `deploy` and `upgrade` refuse answers-file keys that no placeholder reads, so a misspelt key no longer drops an answer silently.
- `deploy` renders everything, the catalogue included, before writing, so bad input never leaves a half-built folder.
- The metric list is validated more strictly (names, ids, dimensions, text fields). Connector kinds `input`, `driver` and `other` are accepted.
- The Datarails adapter no longer assumes a sum when the roll-up is missing. It marks the roll-up `unknown`, and the watch list says so. A metric whose status is not active (for example processing) is flagged.
- `upgrade` no longer brings back template files a person deleted or moved. It reports a removed region and a suggested context heading once, not on every run, and writes nothing when there is nothing to change.
- `scrub` exempts only a pinned action's own SHA, not other hex on the same line.
- Connector guide: a query without a scenario filter can mix actuals, budget and forecast; always filter the scenario.

## 0.1.0 - 2026-11-02

First release.

### Added

- The `CFO OS` folder template: `START HERE.md`; `00 System` with the Claude Project instructions, the folder map, a changelog and connector test questions; `01 Context` with company, people, data, glossary and calendar files; `02 Rules and style` with a rules file and five output templates (management memo, variance table, board pack, management accounts, investor update); `03 Memory` with key findings, decisions, open questions and lessons; `04 Workflows` with a workflow template and twelve workflows (start session, close session, forecast critique, cash runway, month-end close, management accounts, board pack, quarterly accounts, investor reporting, budget, year-end and audit, board or investor question); and READMEs for `05 Periods` to `08 Archive`.
- The `cfo-os` command: `deploy`, `upgrade`, `check`, `pasted`, `catalogue` and `scrub`.
- A neutral metric list format and an adapter for the Datarails FinanceOS connector's metric list.
- Docs: memory model, working with a connector, the first connector guide, folder map, deploy, upgrade, writing a workflow.
- A fictional example answers file and metric list.

### Template regions

- `00 System/Instructions.md`: `reading-order`, `filing-rules`, `connector-rules`, `every-figure`, `session-close`.
- `00 System/Folder map.md`: `filing-rules`, `who-writes`.
- `00 System/Tests/Test questions.md`: `questions`, `pass-rule`.
- `START HERE.md`, every file in `04 Workflows/` and every file in `02 Rules and style/Templates/`: `body`.
